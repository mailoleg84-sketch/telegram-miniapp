## 1. Общая оценка проекта

Проект — **зрелый MVP с понятной доменной логикой**, но с признаками быстрого органического роста. Стек целостный: `aiogram` (бот-лаунчер) + `aiohttp` (API) + `asyncpg`/PostgreSQL (Neon) + OpenAI (чат, TTS, Whisper, Realtime, картинки). Бот делает одно — открывает Mini App; всё обучение внутри SPA.

**Сильные стороны:**
- Чёткая продуктовая модель (родитель + ребёнок, возрастные группы 5–18, маршрут дня).
- Грамотная авторизация: HMAC-подпись Telegram `initData` + подписанный fallback с доменным разделением ключа. `user_id` всегда берётся из подписи → подделать чужой доступ нельзя.
- Есть тесты на критичную доменную логику (машина состояний урока, safety-guard, целостность банка слов).
- `webapp/lesson_engine.py` — образцово чистый детерминированный модуль без побочных эффектов.

**Слабые стороны:**
- Два файла-гиганта (`server.py` 3819 стр., `app.js` 4806 стр.) концентрируют почти всю логику.
- Нет сервисного слоя и модульной структуры → высокая стоимость изменений и низкая тестируемость частей.
- Состояние в памяти и эфемерный диск Render → допущение «один инстанс», незаметное до роста нагрузки.

**Готовность к развитию: ~7/10.** Запускать и эксплуатировать на небольшой аудитории можно. Для роста (новые тренировки, подписки, аналитика) сначала нужен рефакторинг ядра и вынос состояния наружу.

## 2. Архитектурные проблемы

### 2.1 God-objects
- **`webapp/server.py` (3819 стр.)** смешивает: HTTP-роутинг, бизнес-логику (тест уровня, урок дня, геймификация), 430 строк SVG-генератора (`452-883`), rate-limiter, ~70 payload-билдеров, 40 обработчиков и 165 строк inline-данных `LEVEL_TESTS` (`1845-2010`).
- **`webapp/static/app.js` (4806 стр.)** — единый файл без модулей; весь фронтенд в одном скоупе.

### 2.2 Отсутствие сервисного слоя
Обработчики `server.py` вызывают `database.*` напрямую и содержат бизнес-цепочки из 8–10 `await` (`api_chat_send:3251`, `api_vocab_finish:2852`, `api_daily_progress:2613`). Логику невозможно протестировать в отрыве от HTTP.

### 2.3 Протечка слоёв
`database.py` импортирует `build_vocabulary_visual` из `webapp/vocabulary_visualizer.py` (`database.py:14`) и вызывает её в сидере — слой данных знает о слое визуализации (обратная зависимость).

### 2.4 Жёсткая связанность frontend ↔ backend
`app.js` обращается к полям ответов по строковым литералам (`result.reply`, `result.words[i].word_id` и т.д.) и хардкодит >30 путей API. Нет схемы/версионирования: переименование поля на бэке молча ломает фронт.

### 2.5 Контент внутри кода
`LEVEL_TESTS` (`server.py:1845-2010`) и `TOPIC_PLANS` (`lesson_engine.py`) — учебный контент, перемешанный с кодом. Лучше вынести в `data/`.

## 3. Потенциальные баги

> Severity: 🔴 критично · 🟠 высокий · 🟡 средний · 🟢 низкий

### Словарь / тренировки
- 🟡 **Рассинхрон переводов.** `data/words.py` (`CORE_WORDS`) и `data/single_words_5000.py` пересекаются (напр. `apple`), но без единого источника истины. Правка перевода в одном файле не отражается в другом → противоречивые данные на карточках.
- 🟢 **Шаблонные примеры.** В банке 5000 слов примеры вида `"Let's learn the word X."` — не настоящий контекст употребления (не баг, но дефект качества обучения).

### Голосовой модуль
- 🟠 **Зависание Realtime-инициализации.** `_post_realtime_client_secret` (`openai_service.py:~1136-1201`) при ошибке делает retry; суммарно соединение может висеть ~50 с без общего таймаута на обработчик → у ребёнка «застывший» экран.
- 🟡 **Двойной вызов OpenAI** при `_needs_russian_repair` (`openai_service.py:~1481`) — ×2 латентность и стоимость на «русскоязычный ход»; при сбое второго вызова поведение неочевидно.
- 🟡 **Три разные нормализации `age_group`** (`lesson_engine.py:134`, `server.py:1569`, `openai_service.py:909`) — расхождение между ними даёт разный возрастной профиль в чате/голосе/Realtime для одного ребёнка.

### Генерация картинок
- 🟠 **«Битые» картинки после деплоя.** URL сгенерированной картинки хранится в БД (`database.py:632-651`), но файл — на эфемерном диске Render. После деплоя файла нет, а `_generated_vocab_url_exists` может не покрывать все пути → либо пустая картинка, либо повторная платная генерация.
- 🟢 **Лишняя работа.** `_problem_word_dict` (`server.py:~1075`) вызывает весь `_word_dict` (с `build_vocabulary_visual`) ради одной транскрипции.

### Сохранение прогресса
- 🔴 **Потеря результата тренировки.** Одноразовые токены тренировок в памяти (`_training_attempts`, `server.py:3033`). При рестарте Render (free-план рестартует на каждом деплое и после 30 мин простоя) или при 2+ инстансах `_consume_training_attempt` вернёт `False` → начисление очков/прогресс не запишется, хотя ребёнок ответил верно.
- 🟡 **N+1 при finish** (`server.py:2903, 3000`) — `update_progress` в цикле; при частичном сбое соединения часть слов может не записаться без атомарности.

### Авторизация
- 🟡 **Fallback-токен живёт 24 ч** без инвалидации/привязки к сессии (`auth.py:30`). При утечке ссылки (логи, history) — сутки доступа от имени пользователя.
- 🟡 **Промпт-инъекция через историю.** История чата подаётся в OpenAI без фильтрации (`server.py:~3280`); `safety_guard` (`openai_service.py:525-577`) — наивный keyword-matching, обходится дефисами/опечатками.
- ✅ **ИСПРАВЛЕНО (Этап 1):** webhook без секрета — теперь fail-fast; отсутствие лимита Realtime — добавлен суточный лимит; отсутствие валидации типа аудио — добавлена проверка magic-bytes.

### База данных
- 🟢 **f-строка с именем таблицы** в `delete_user_account` (`database.py:461`) — значения захардкожены, инъекция невозможна, но антипаттерн.
- 🟡 **Рост `conversations` без очистки** — таблица копится бесконечно; ✅ индекс `conversations(user_id, id DESC)` уже добавлен в Этапе 1, но политики ретенции по-прежнему нет.

## 4. Проблемы производительности

- 🟠 **N+1 запросы.** `api_vocab_quiz` (`server.py:2841`) и `api_word_hunt_start` (`2950`) запрашивают дистракторы **на каждое слово** → до 11 последовательных round-trip к Neon (50–100 мс каждый) = +0.5–1 с на сессию. `update_progress` в цикле на finish (`2903, 3000`).
- 🟠 **Эфемерный диск для кэшей.** Кэш TTS, сгенерированных картинок и Pixabay-фото на эфемерном диске Render → стирается при каждом деплое → повторная оплата OpenAI за уже сгенерированное.
- 🟡 **Блокирующий I/O в event loop:**
  - `index.html` читается `read_text()` **на каждый запрос** (`server.py:3651`).
  - `_seed_words` вызывает `build_vocabulary_visual` 5000× синхронно при каждом старте (`database.py:267`).
  - `_evict_cache_dir` делает `glob`+`stat` синхронно прямо в обработчиках.
- 🟡 **`ORDER BY RANDOM()`** в ~12 местах (`database.py:658-766`) — full scan + sort, деградирует при росте банка слов.
- 🟡 **`app.js` 196 КБ без gzip/минификации** — `add_static` не сжимает; ~2 с на 3G у ребёнка.
- 🟡 **Двойной вызов OpenAI** в голосе (см. 3) — лишняя стоимость и латентность.
- 🟡 **Голосовой ход** (`_voice_text_turn_payload:3406`) — ~10 последовательных DB-запросов + 1–2 OpenAI, без `asyncio.gather`.
- ✅ **ИСПРАВЛЕНО (Этап 1):** добавлены индексы на `conversations`, `user_progress`, `daily_lessons`, `words(age_group)` — снимает seq scan на горячих путях.

## 5. Проблемы безопасности

> Секреты не читались и не копировались — анализ только по схеме обращения с ними.

- ✅ **ИСПРАВЛЕНО (Этап 1) — незащищённый webhook.** Раньше `secret_token=... or None` отключал проверку. Теперь бот в webhook-режиме не стартует без `TELEGRAM_WEBHOOK_SECRET`. **Действие для деплоя:** задать секрет в Render env.
- ✅ **ИСПРАВЛЕНО (Этап 1) — финансовый риск Realtime.** Добавлен суточный per-user лимит на дорогие сессии (`REALTIME_DAILY_SESSION_LIMIT`, 429 при превышении).
- ✅ **ИСПРАВЛЕНО (Этап 1) — нет CSP / валидации аудио.** Добавлен мягкий `Content-Security-Policy` и проверка magic-bytes загружаемого аудио.
- 🟡 **Safety-guard обходится** промпт-инъекцией (наивные подстроки) — значимо для детского продукта; встроенные guardrails GPT страхуют частично.
- 🟡 **Fallback-auth TTL 24 ч** без отзыва.
- 🟢 **Стектрейсы в логах Render** (не в HTTP-ответе — клиент видит только «Внутренняя ошибка сервера»).
- 🟢 **Загрузка аудио:** лимит 8 МБ есть; ✅ проверка типа добавлена.

**Что сделано хорошо:** ключи (`BOT_TOKEN`, `OPENAI_API_KEY`, `DATABASE_URL`) не утекают в ответы/фронт; `public_openai_error()` фильтрует сырые ответы провайдера; PII-редакция перед записью истории; админ-эндпоинты проверяют `ADMIN_USER_IDS` из подписи; SQL параметризован; XSS в чате закрыт (`textContent`). Конфиг секретов читается из env, дефолты безопасны.

## 7. Что мешает масштабированию

- **Состояние в памяти** (`_rate_buckets`, `_photo_ip_buckets`, `_training_attempts`) — при горизонтальном масштабировании лимиты умножаются на число инстансов и обходятся, токены тренировок «теряются» между инстансами. Блокирует включение 2+ инстансов.
- **Эфемерный диск** для кэшей — нет постоянного хранилища артефактов (картинки, аудио). Мешает удешевлять и масштабировать генерацию.
- **Пул `max_size=5`** (`database.py:50`) вплотную к лимиту Neon free — при 2 инстансах исчерпание соединений.
- **God-objects без слоёв** — добавление новой тренировки/режима требует правок в 3819-строчном `server.py` и 4806-строчном `app.js` с высоким риском конфликтов и регрессий.
- **Нет версионирования API** — мешает развивать фронт и бэк независимо, выпускать новые клиенты.
- **Нет аналитической модели событий** — для подписок/аналитики потребуется слой событий, которого нет (всё считается ad-hoc по таблицам).
- **Сид при каждом старте** (`_seed_words` DELETE+executemany 5000 слов) — замедляет старт и плохо масштабируется с ростом данных; мешает быстрым деплоям.
- **Нет тестов на `database.py` и интеграционных** — любой рефакторинг ради масштабирования идёт «вслепую».

## 9. Что лучше не трогать без необходимости

> Рабочие и аккуратно сделанные части — менять только с тестами и веской причиной.

- **`webapp/auth.py`** — проверка подписи `initData` и fallback с доменным разделением ключа. Корректно использует `hmac.compare_digest`. Любая «оптимизация» здесь рискует открыть дыру в авторизации. Покрыто поведением через тесты.
- **`webapp/lesson_engine.py`** — чистая детерминированная машина состояний урока, хорошо покрыта тестами. Менять только вместе с тестами.
- **Safety-слой контента для детей** (`BLOCKED_SEED_WORDS`, `redact_personal_data`, safety-guard, фильтр банка слов) — даже при усилении нельзя ослаблять; есть тесты (`test_prompt_injection_is_blocked`, `test_secret_request_is_blocked`, целостность 5000 слов).
- **`data/single_words_5000.py`** — большой сгенерированный банк, сбалансирован по возрастам и проверен тестом. Ручные правки легко ломают баланс/уникальность — менять только генератором.
- **Контракт payload между бэком и `app.js`** (`public_lesson_state`, `_*_payload`) — фронт жёстко завязан на форму ответов; менять формат только синхронно с `app.js` и тестом `test_navigation_*`.
- **Схема БД / миграции в `init_db`** — идемпотентные `CREATE TABLE/ALTER ... IF NOT EXISTS`. Удалять/переименовывать колонки опасно для существующих данных в Neon.
