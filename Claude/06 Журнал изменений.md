## 2026-06-11 — «Живые примеры» к словам + аудит безопасности банка (расширение BLOCKED_SEED_WORDS)

Два связанных изменения: новая генерация примеров употребления + устранение небезопасных слов, вскрытых при адверсариальной проверке этой же генерации.

**1. Живые примеры (бесплатно, детерминированно).** Раньше пример был один шаблон на все 5000 слов (`Let's learn the word X.`). Теперь пример строится при импорте из слова/части речи/возраста (как транскрипции — производное, не дублируем данные; `data/words.py`: блок `_build_example`/`_example_category`/`_EXAMPLE_TEMPLATES`, применяется в `LEARNING_WORDS`).
- **Принцип «качество не падает»:** настоящие примеры употребления строятся ТОЛЬКО по надёжным курируемым спискам (NOUNS/VERBS/ADJECTIVES + расширение ядра); для остального — безопасный вариативный учебный фрейм с кавычками («Let's practice 'X'.»), грамматически корректный для любой части речи.
- **Почему не эвристики:** адверсариальная проверка (workflow, 5 ревьюеров по 5000 примеров) доказала, что морфология и русский перевод как сигнал части речи дают массу ошибок, недопустимых для детей (`cop → It is very cop`, `first → That looks first`, `aimed → It is very aimed`, переходные глаголы без объекта). Эти пути отвергнуты.
- **Расширение ядра (решение «расширить»):** +196 вручную проверенных частых однозначных слов (129 счётных сущ., 43 прил., 24 непереходных глагола — отдельная категория с шаблонами без объекта). Настоящие примеры: 327 → **517 (10%)**; остальные 90% — корректные вариативные фреймы.
- Инварианты (guard-тест `tests/test_word_examples.py`): пример всегда содержит целевое слово (для gap-вопросов), ≤80 символов, непустой, детерминирован, старый шаблон вычищен. **6 проверок.**

**2. ⚠️ Безопасность банка (критично).** Та же проверка вскрыла **предсуществующую** проблему: банк `data/single_words_5000.py` содержал слова, недопустимые для детей 5–18 (слур `blacks`=«негры», мат `wtf`/`sucks`/`suck`, интернет-сленг, оружие/насилие, оскорбления, смерть, наркотики, война/национальности). По решению пользователя («блокировать агрессивно, включая спорные») `database.BLOCKED_SEED_WORDS` расширен с 50 до **267 слов**; **81 слово отфильтровано** из детского банка (4919 остаётся). Механизм — защита в глубину (данные НЕ удаляются, слова не попадают в БД при сидинге). Страж `BlockedSeedWordsGuardTests`.

**Проверка:** py_compile (config/database/words/server) OK, `node --check app.js` OK, **177 passed** (171 + 6 новых guard-тестов: 5 на инварианты примеров + 1 на блок-лист). Бизнес-логика выборки слов не менялась.
**Git:** не закоммичено — жду разрешения (изменение детского контента + safety).

## 2026-06-09 — SRS: интервальное повторение (Leitner), движок

Режим «Повторение» переведён с «только ошибочные слова» на **интервальное повторение по времени (SRS, Leitner)**. Теперь освоенные слова не исчезают навсегда, а возвращаются через растущие интервалы — это даёт долгую память (приоритет №3). **Что сделано (`database.py`):**
- Схема `user_progress`: `+ srs_box INTEGER DEFAULT 0`, `+ next_review_at TIMESTAMP` (аддитивно, `ADD COLUMN IF NOT EXISTS`) + индекс `user_progress_due_idx (user_id, next_review_at)`.
- «Коробки» 0..5 → интервалы: box0 — сразу, далее 1 / 3 / 7 / 16 / 35 дней.

- `get_review_word`: подбор «пора повторить» (`next_review_at IS NULL OR <= NOW()`), самые просроченные первыми. Ошибочные стоят в box0 (срок = сейчас), освоенные возвращаются по интервалу.
- **Однократная идемпотентная миграция** старых строк: `srs_box` из `review_streak`, срок — старые «на повторение» сразу, остальные от `last_seen` по интервалу (`WHERE next_review_at IS NULL` → на повторных деплоях 0 строк, без флуда «Повторения» после деплоя).

**Фронтенд не менялся** — режим «Повторение» уже есть; изменился только подбор слов и их перепланирование.

**Единый источник истины (выровнено сразу):** `get_user_dictionary` (фильтр «review» и колонка `needs_review`) и `get_dictionary_summary.review_words` переведены на тот же SRS-критерий `next_review_at IS NULL OR <= NOW()`, что и `get_review_word`. **Адверсариальная проверка перед пушем:** 4 независимых ревьюера (синтаксис Postgres, логика Leitner, безопасность миграции, регрессии). Критичных багов нет, SQL исполним на Neon.
