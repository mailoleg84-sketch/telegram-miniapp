## 2026-06-09 — Картинки слов: логичнее и точнее (бесплатно), шаг 1

Картинки в режиме изучения слов формируются осмысленнее, без платной генерации.

**Проблема (была):** фото Pixabay тянулось для ЛЮБОГО слова без эмодзи — даже абстрактного (`allow`, `reason`, прилагательные) → случайная картинка; запрос шёл голым английским словом → омонимы (`bat`, `spring`, `bank`) давали неверный смысл.

**Что сделано:**
- `webapp/server.py` `_vocab_card_image_url`: **гейт фото по `visual_type`** — фото только для конкретных типов (`object`/`action`); для абстрактных/грамматических остаётся осмысленная SVG-сцена. Плюс проброс топика в запрос.
- `webapp/server.py`: оба вызывающих (`_word_image_url`, `_word_dict`) передают `visual_type` и топик; `vocabulary_photo_handler` отдаёт топик в поиск.
- `webapp/free_images.py` `fetch_word_illustration(word, topic)`: топик → **Pixabay `category`** (animals/food/sports/transportation/…) — резко поднимает релевантность и снимает омонимию (например «bat» в animals vs sports).

**Эффект:** абстрактные слова больше не получают случайные стоковые фото; конкретные — фильтруются по теме. Всё бесплатно, кэш уже есть. Бамп `APP_VERSION` не нужен (серверная логика).

**Тесты:** новый `tests/test_vocab_images.py` (10 тестов: гейт по типу, эмодзи/sensitive, топик, маппинг категорий). Весь набор — **114 passed** (было 104).

**Дальше:** шаг 2 — расширить словарь эмодзи `WORD_EMOJI` по банку 5000 слов (надёжнее всего); шаг 3 (опц.) — Openverse-фолбэк.

## 2026-06-09 — Persistent storage, инкремент 1 (слой хранилища + CACHE_ROOT)

Введён слой файлового хранилища и конфигурируемый корень кэша — фундамент для устойчивых кэшей (картинки/озвучка/фото переживают деплой). **Без новых зависимостей.** В дефолтной конфигурации поведение байт-в-байт прежнее.

**Что сделано:**
- Новый `webapp/storage.py`: `LocalDiskStorage` (read/write/exists/delete/evict), `evict_dir`, корень `CACHE_ROOT` из env (дефолт `<static>/generated`), три хранилища (картинки/аудио/фото). Интерфейс задокументирован под будущий backend S3/R2.
- `webapp/server.py`: каталоги кэшей берутся из storage (единый источник); `_evict_cache_dir` делегирует в `storage.evict_dir` (имя функции сохранено); добавлена раздача сгенерированных картинок из `CACHE_ROOT` своим маршрутом, если он вынесен за `static` (с защитой от path-traversal).
- `.env.example`: документирован `CACHE_ROOT`.

**Как включить персистентность на Render:** подключить persistent disk и задать `CACHE_ROOT` на точку монтирования — кэши перестанут стираться при деплое (конец повторной оплаты OpenAI за уже сгенерированное).

**Тесты:** новый `tests/test_storage.py` (6 тестов: roundtrip, eviction + .none-исключение, env-override). Relocated-сценарий (вынесенный CACHE_ROOT) проверен вживую через TestClient: картинка отдаётся (200), traversal → 404. Весь набор — **99 passed** (было 93, +6).

**Дальше (инкремент 2):** облачный backend S3/Cloudflare R2 (та же сигнатура) — отдельным шагом, потребует зависимости и аккаунта.

## 2026-06-09 — Усиление safety-guard и фильтрация промпт-инъекций

Защита детского чата от обходов и ролевых инъекций (приоритет №8). Существующее поведение сохранено, существующие safety-тесты не тронуты.

**Что сделано (`webapp/openai_service.py`):**

**Тесты:** новый `tests/test_safety_guard.py` (11 тестов: обходы guard, нейтрализация токенов, защита от false-positive на нормальном тексте). Весь набор — **86 passed** (было 75, +11).

## 2026-06-09 — Параллелизация голосового/чат-хода (asyncio.gather)

Независимые запросы к БД в голосовом и чат-ходе выполняются параллельно — меньше латентности на ход. Логика и порядок зависимых операций сохранены.

**Что распараллелено (через `asyncio.gather`):**
- старт: `get_ai_usage_today` (гейт лимита) ∥ `get_user` (профиль);
- ход пользователя (voice): `add_message("user")` ∥ `_advance_voice_lesson_state(…,"user")` — записи в разные таблицы; `get_recent_messages` — строго после;
- ход ассистента (voice): `add_message("assistant")` ∥ `_advance_voice_lesson_state(…,"assistant")`.

**Что осталось последовательным (зависимость по данным):** история после записи сообщения; `chat_reply` после истории; финальный `get_ai_usage_today` после `add_ai_usage`.

**Файлы:** `webapp/server.py` (`api_chat_send`, `_voice_text_turn_payload`).
**Тесты:** новый `tests/test_voice_turn.py` (2 теста с моками: оркестрация + ветка лимита). Весь набор — **75 passed** (было 73, +2).
**Совместимость:** форма ответа, учёт usage и состояние урока не изменились.

## 2026-06-09 — Устранение N+1 в квизах и тренировках

Оптимизирована выборка слов: было 1+N запросов на сессию, стало 2; запись прогресса — одним батчем. Поведение сохранено 1:1.

**Что сделано:**
- `database.py`: новая `update_progress_bulk(user_id, items)` — один `executemany` вместо N (логика correct/wrong/review_streak идентична `update_progress`).
- `webapp/server.py`:
  - `_pick_distractors(pool, correct_id)` — выбор дистракторов из заранее загруженного пула (`random.sample`, исключая правильный id);
  - `_build_vocab_question` / `_build_word_hunt_round` берут дистракторы из пула (fallback на старый запрос, если пул мал) — стали чистыми, тестируются без БД;
  - `api_vocab_quiz` / `api_word_hunt_start` тянут пул **одним** запросом;
  - `api_vocab_finish` / `api_word_hunt_finish` пишут прогресс одним `update_progress_bulk`.

**Тесты:** новый `tests/test_quiz_building.py` (7 тестов: `_pick_distractors`, билдеры, fallback). Весь набор — **73 passed** (было 66, +7).
**Эффект:** −0.5…1 с латентности на загрузку квиза; меньше нагрузки на Neon.
**Совместимость:** форма ответов и подсчёт очков не изменились.
