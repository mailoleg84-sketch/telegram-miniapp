## 2026-06-25 — Единая навигация «назад»: общий screenHeader + один обработчик на все экраны

Задача: на каждом вложенном экране должна быть понятная навигация назад — нативный Telegram BackButton **и** видимая кнопка «← Назад», с единой логикой возврата.

**Аудит (сначала проверка, без правок):**
- **Нативный `setBack(...)` уже почти везде корректен** — из ~37 render-функций практически каждая вложенная вызывает `setBack` с разумной целью (vocab→start, dailyWords→lesson, adminDetail→adminUsers, levelQuestion→предыдущий вопрос). Корневые (`renderMenu`/`renderRegistration`/`renderLoggedOut`) и `renderError` — `setBack(null)`. «Единая логика возврата» по сути уже была.
- **Видимая кнопка «← Назад» — только на ~9 экранах и вразнобой**: `backToProfile` (дублировался в 5 экранах), `reportHome`, `historyHome` («← Назад»), `adminUsersBack` («К админке»), `adminDetailBack` («К пользователям») — разные id и подписи. ~28 экранов видимой кнопки не имели.
- CSS `screen-header`/`screen-back` не существовало.

**Что сделано (`database.py` не тронут):**
- **`webapp/static/app.js`:** добавлен helper **`screenHeader(title, {showBack, subtitle, backLabel})`** (заголовок + кнопка `.screen-back`) и **один делегированный обработчик** на `app`: клик по `.screen-back` → `haptic()` + текущий `state.back()` — ровно та же цель, что и нативный BackButton. Поэтому видимая кнопка и BackButton всегда согласованы, без per-screen `onclick` и зависших обработчиков. Заголовки `<h1>` на ~33 вложенных экранах заменены на `${screenHeader("…")}`. На экранах теста уровня (после регистрации) back скрыт через `showBack: !afterRegistration`, чтобы не было «мёртвой» кнопки.
- **Удалены 5 ad-hoc back-кнопок** (`backToProfile`/`reportHome`/`historyHome`/`adminUsersBack`/`adminDetailBack`) и их `onclick` — теперь назад даёт единый header.
- **Чат:** `setBack(renderMenu)` поднят в начало `renderChat` (back доступен сразу при входе, ещё до загрузки истории); в конце функции он переопределяется на `cleanupChat()`+`renderMenu`. В шапку чата добавлена видимая `.screen-back` — она идёт через тот же `state.back`, т.е. тоже зовёт `cleanupChat()`. При ошибке загрузки — `renderError` (reload), пользователь не застревает.
- **`webapp/static/styles.css`:** новые классы `.screen-header`/`.screen-back`/`.screen-subtitle` (компактная кнопка на тех же палитра-переменных, что и `.btn`).
- **`config.py`:** `APP_VERSION` `…-v154` → **`…-v155`** (ассеты версионируются через `?v=APP_VERSION`; без бампа новый `app.js`/`css` не дошёл бы до детей).
- Отдельно: незакоммиченная SVG-правка `_child_figure` **откачена** (`git checkout webapp/svg_renderer.py`) — она не решала проблему ясности картинок; дерево чистое под навигацию. Палитра/кэш v154 (в проде) сохранены.

**Тесты:** новый `tests/test_navigation.py` (сканирование исходника `app.js`): у вложенных экранов есть `screenHeader`/`.screen-back`; setBack у экрана или его загрузчика; корневые прячут back (`setBack(null)`, без header); чат-back зовёт `cleanupChat()` и показывает back при входе; один делегированный обработчик через `state.back`; нет ad-hoc back-id; `quizPromptCard` отдаёт приоритет `image_url` над большим эмодзи; карточки слов = SVG, не `/vocabulary-photo`. ## 2026-06-24 — Единая палитра SVG-карточек: убран случайный accent-цвет и иконка, + cache-busting

Проблема: даже после v153 (все карточки → SVG) карточки выглядели разнородно. Корень — **случайность в рендерере** `webapp/svg_renderer.py`, а не маршрутизация (она уже едина): (1) `accent = "#" + seed[:6]` — вторичный цвет брался из среза SHA1-хэша слова → у каждого слова свой случайный, часто кричащий цвет (особенно заметно в сценах: мяч `in/on/under`, вторая фигурка в `situation`, круг результата в `because`); (2) object-слово без иконки получало случайную «не ту» иконку по хэшу (`spoon` → атом); (3) SVG отдаётся с `max-age=604800`, а URL `/vocabulary-visual.svg` не версионировался → новая художка не появилась бы у детей ~неделю.

Сделан реально оставшийся пункт 7 (единая художка) + пункт 9 (cache-busting).

**Что сделано (`database.py` не тронут):**
- **`webapp/svg_renderer.py`:** новый `TOPIC_ACCENTS` + `_accent_for(color)` — **детерминированный** гармоничный вторичный цвет от палитры темы (синий → `#ff9f43` и т.д.). `accent = "#"+seed[:6]` заменён на `_accent_for(color)` в обеих функциях. `_word_image_style` переписан: иконка слова → иконка темы → нейтральный `book`; убрана случайная запасная иконка (`FALLBACK_IMAGE_ICONS`/хэш) и ненужный `import hashlib`.

**Результат (offline-рендер):** слова одной темы теперь делят **один** контролируемый accent. Пример `school`: `in`/`on`/`under` → одинаковая палитра `#2481cc / #dff3ff / #eef8ff / #ff9f43` (раньше у каждого свой случайный цвет); `brave`/`kind` → так же. URL карточек содержат `iv=20260624-kids-v154`. Случайные цвета/иконки из карточек исчезли; «резкая разница между карточками» убрана.

## 2026-06-24 — Фикс крэша деплоя Render: пустой числовой env ронял `config` (`float('')`)

Лог Render показал **истинную** причину застрявшего деплоя (дополняет запись ниже): билд нового кода падал на старте —
`File "/app/config.py", line 114 … OPENAI_DAILY_COST_LIMIT_USD = float(os.getenv("OPENAI_DAILY_COST_LIMIT_USD", "0")) → ValueError: could not convert string to float: '' → Exited with status 1`.
В Render переменная `OPENAI_DAILY_COST_LIMIT_USD` задана **пустой строкой** `''`. `os.getenv("X","0")` отдаёт `''` (переменная существует, но пустая → дефолт «0» не берётся), а `float('')` роняет импорт. Поэтому КАЖДЫЙ деплой после появления этой строки падал, а старый инстанс `v142` оставался жить → пользователь видел старые фото. Причина не в коде картинок, не в кэше и не в БД — в хрупком разборе числовых env.

**Что сделано (корневой фикс, `database.py` не тронут):**
- **`config.py`:** добавлены толерантные хелперы **`_env_int` / `_env_float`** (пустая строка/пробелы/мусор → default, без ValueError). Все ~21 числовых env-параметров переведены с `int/float(os.getenv(...))` на них (лимиты, стоимости, токены, порт, очки игры).
- **`webapp/server.py`, `webapp/routes_chat_voice.py`:** ещё 3 таких же места (`VOCAB_PHOTO_CACHE_MAX_FILES`, `VOCAB_IMAGE_CACHE_MAX_FILES`, `AUDIO_CACHE_MAX_FILES`) переведены на импортированный `_env_int` — чтобы пустой env не ронял импорт и этих модулей.

**Проверка (воспроизведение боевого условия):** запуск с `OPENAI_DAILY_COST_LIMIT_USD='' VOCAB_PHOTO_CACHE_MAX_FILES='' AUDIO_CACHE_MAX_FILES='' CHAT_HISTORY_LIMIT='' OPENAI_INPUT_COST_PER_1M=''` → `import config` / `import webapp.server` / `import webapp.routes_chat_voice` **проходят** (default'ы: 0.0/8/0.75/800/4000). До фикса эта же команда падала с тем самым `ValueError`. `py_compile` — OK; `node --check app.js` — OK; полный набор — **262 passed**.

**Результат:** деплой нового кода больше не крэшит на пустом числовом env. После пуша Render должен подняться на `v152`, и тогда заработает уже сделанный фикс картинок (`d28223b`): `lesson`/`answer` → учебная SVG-сцена, `/vocabulary-photo?w=lesson` → 302 SVG. Рекомендация владельцу: в Render задать `OPENAI_DAILY_COST_LIMIT_USD` числом (`10` под бюджет или `0` = выкл), а не оставлять пустым.
**Git:** не закоммичено — жду разрешения.

## 2026-06-24 — Архитектура картинок: фотосток off, строгий allowlist `PHOTO_SAFE_OBJECTS`

Проблема: картинки к словам сбивали ребёнка (`lesson` → фото руки с карандашом, `answer` → заполнение анкеты). Корень — не отдельные слова, а слишком мягкая политика источников: фото разрешалось для любого из ~90 слов курируемых object-наборов, а `VOCAB_FREE_PHOTOS` по умолчанию включён. Цель — `word → учебный смысл → контролируемая визуализация`, без случайного фотостока.

**Диагностика (read-only):** в текущем коде `lesson`/`answer`/`class`/`visited`/`because`/`the` уже отдавали SVG (не фото), прод-БД чистая (`generated_image_url=''`, `status='missing'`). Значит видимые фото — устаревший браузер/Telegram-кэш (старые картинки отдавались с `Cache-Control: max-age=604800`). Архитектура оставалась хрупкой → закрыто корнево.

**Что сделано (архитектурно, `database.py` не тронут):**

## 2026-06-09 — SRS: интервальное повторение (Leitner), движок

Режим «Повторение» переведён с «только ошибочные слова» на **интервальное повторение по времени (SRS, Leitner)**. ## 2026-06-09 — Токены тренировок переживают рестарт через Neon (Upstash не нужен)

Одноразовые токены тренировок теперь по умолчанию хранятся в **уже подключённой базе Neon (PostgreSQL)** — переживают рестарт/деплой без отдельного сервиса Redis/Upstash. Это закрывает единственную причину, по которой Redis был «нужен»: токены критичны к персистентности, rate-limit — нет.

**Новый порядок бэкендов** (выдача и гашение токена — одинаково): Redis (если задан `REDIS_URL`) → **Postgres/Neon (дефолт)** → in-memory (фолбэк при сбое БД, чтобы не ронять пользователя).

**Что сделано:**
- `database.py`: таблица `training_tokens (token PK, user_id, word_id, expires_at)` + индекс по `expires_at` (создаётся в `init_db()` автоматически на ближайшем деплое). Функции `issue_training_token()` (чистит протухшие + INSERT с TTL через `make_interval`) и `consume_training_token()` (атомарный `DELETE … WHERE token AND user_id AND word_id AND expires_at>=NOW() RETURNING` — одноразовость + валидация в одном запросе).
- `webapp/server.py`: `_issue_training_attempt`/`_consume_training_attempt` — добавлена ступень Postgres между Redis и in-memory (каждый бэкенд под `try/except` с `log.warning(exc_info=True)` и фолбэком дальше).
- Тесты: `tests/test_database.py` +3 (`TrainingTokenSqlTests` — ветка SQL/порядок параметров/маппинг через FakePool, без боевой БД). Тест single-use и тест фолбэка переведены так, чтобы **не стучаться в боевой Neon** (БД-функции замоканы → доходим до in-memory).

**Rate-limit оставлен in-memory** — не критичен к персистентности, и БД-запрос на каждый HTTP-запрос был бы лишней нагрузкой.

**Тесты: 153 passed** (было 150). Время прогона ~5–6 с дают холодный импорт `aiogram`/`asyncpg` (разово на процесс), не сеть.

**Итог для прод:** ничего настраивать не нужно — таблица создастся сама в `init_db()`, токены сразу переживают рестарт на текущем Neon. Redis остаётся опциональным (`REDIS_URL`), Upstash не требуется.
