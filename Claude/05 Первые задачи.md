# Задача 1 — Кэшировать `index.html` в памяти

## Проблема
`index_handler` читает `index.html` с диска синхронно на **каждый** запрос — блокирует event loop.

## Почему это важно
Чем больше пользователей, тем заметнее блокировки; это самый дешёвый прирост стабильности и скорости без риска для логики.

## Что нужно сделать
Прочитать `index.html` один раз при старте приложения, подставить `APP_VERSION`, отдавать из памяти.

## Какие файлы вероятно будут затронуты
- `webapp/server.py` (`index_handler`, `create_app` / on_startup)

## Риск
🟢 Низкий. Учесть удобство dev (опциональный флаг перечитывания).

## Как проверить результат
- `py_compile webapp/server.py`
- Открыть Mini App — страница грузится, версия подставлена.

## Готовый промт для Claude Code
```text
Прочитай CLAUDE.md. Выполни только задачу: кэшировать index.html в памяти при старте приложения и отдавать из кэша (с подстановкой APP_VERSION), вместо чтения с диска на каждый запрос в index_handler (webapp/server.py). Не меняй другую логику. После изменения запусти py_compile и обнови Claude/06 Журнал изменений.md.
```

# Задача 2 — gzip и кэш-заголовки для статики

## Проблема
`app.js` (~196 КБ) отдаётся без сжатия и без `Cache-Control` — медленно на мобильном интернете у детей.

## Почему это важно
Прямое влияние на скорость первой загрузки на слабых устройствах/сети.

## Что нужно сделать
Включить gzip для текстовой статики (`.js/.css/.html/.svg`), добавить `Cache-Control` и версионирование статики через `?v=APP_VERSION`.

## Какие файлы вероятно будут затронуты
- `webapp/server.py` (`create_app`, отдача статики)
- `webapp/static/index.html` (подключение с `?v=`)

## Риск
🟢 Низкий. Следить, чтобы версионирование инвалидировало кэш при деплое.

## Как проверить результат
- `node --check webapp/static/app.js`, `py_compile webapp/server.py`
- В DevTools: ответ `app.js` приходит gzip, есть `Cache-Control`.

## Готовый промт для Claude Code
```text
Прочитай CLAUDE.md. Выполни только задачу: включить gzip-сжатие текстовой статики и добавить Cache-Control для /static в aiohttp-приложении (webapp/server.py), плюс версионирование подключения app.js/css через ?v=APP_VERSION в index.html. Не трогай другую логику. После изменения запусти node --check и py_compile, обнови Claude/06 Журнал изменений.md.
```

# Задача 3 — Логировать битый JSON в `_safe_json`

## Проблема
`_safe_json` молча возвращает `{}` при невалидном теле запроса — ошибки клиента маскируются.

## Почему это важно
Упрощает диагностику проблем фронтенда без изменения поведения.

## Что нужно сделать
Добавить `log.warning` с путём запроса при ошибке парсинга JSON. Поток управления не менять.

## Какие файлы вероятно будут затронуты
- `webapp/server.py` (`_safe_json`)

## Риск
🟢 Очень низкий.

## Как проверить результат
- `py_compile webapp/server.py`, тесты зелёные.

## Готовый промт для Claude Code
```text
Прочитай CLAUDE.md. Выполни только задачу: в функции _safe_json (webapp/server.py) добавить log.warning с путём запроса при ошибке парсинга JSON, не меняя поток управления и возвращаемое значение. Запусти тесты и py_compile, обнови Claude/06 Журнал изменений.md.
```
