# QA Report: AI English Tutor Kids

Дата проверки: 2026-06-02
Версия кода после безопасных исправлений: `20260602-kids-v62`
Проект: Telegram Mini App + aiohttp backend + PostgreSQL/Neon + OpenAI Responses/Audio/Realtime.

## Итоговый вердикт

Приложение стало заметно безопаснее после текущего прохода: закрыты публичные диагностические команды, добавлены базовые лимиты, закрыт доступ к AI-эндпоинтам для незарегистрированных пользователей, добавлен deterministic safety guard для детских сценариев, убраны сырые Realtime-ошибки и риск попадания секретов в Docker build context.

Но в текущем виде продукт еще нельзя считать готовым к полноценному продакшен-запуску для детей 5-18 лет. Главные оставшиеся риски: хранение чувствительных сообщений ребенка без редактирования/удаления, возможность накручивать прогресс в некоторых учебных режимах, отсутствие полноценной политики удаления данных, устаревшая документация, отсутствие автотестов и CI, а также невычищенные из git артефакты `.venv`/`__pycache__`.

Деплой выполняется через push в `main` и автосборку Render.

## Что было исправлено в этом проходе

1. Админские команды бота
   - `/diag` и `/openai_test` теперь доступны только пользователям из `ADMIN_USER_IDS`.
   - `/version` больше не раскрывает signed fallback URL.
   - `/diag` больше не показывает длину/префикс OpenAI-ключа и signed fallback URL.
   - Файлы: `config.py`, `handlers/start.py`, `render.yaml`.

2. Доступ к API и AI-расходам
   - Для всех API кроме `/api/me` и `/api/register` добавлена проверка, что пользователь зарегистрирован.
   - Добавлен in-memory rate limit:
     - общий API: `API_RATE_LIMIT_PER_MINUTE`, по умолчанию `120`;
     - AI/voice/realtime: `AI_RATE_LIMIT_PER_MINUTE`, по умолчанию `30`.
   - Файлы: `config.py`, `webapp/server.py`, `render.yaml`.

3. Безопасность детских AI-ответов
   - Добавлен deterministic guard до вызова модели:
     - не повторяет адреса/телефоны и другие личные данные;
     - не раскрывает системный промпт;
     - не помогает получать API-ключи;
     - переводит взрослые темы в безопасный учебный сценарий.
   - Файл: `webapp/openai_service.py`.

4. Realtime error handling
   - Ошибки Realtime больше не возвращают ребенку сырые provider/internal details.
   - Клиент получает безопасное сообщение через `public_openai_error`.
   - Файл: `webapp/server.py`.

5. Docker build hygiene
   - Добавлен `.dockerignore`, чтобы в Docker context не попадали `.env`, `.venv`, `__pycache__`, локальные БД, логи и pid-файлы.
   - Файл: `.dockerignore`.

6. Логирование ключей
   - Лог OpenAI-инициализации больше не пишет префикс и длину ключа.
   - Файл: `webapp/openai_service.py`.

7. Env-шаблон
   - Добавлен `.env.example` с безопасными placeholder-значениями.
   - `.gitignore` теперь не скрывает `.env.example`.

8. Render model config
   - `render.yaml` синхронизирован с текущей дефолтной моделью `gpt-5.4-mini`.
   - Обновлены cost env значения под выбранную модель.

9. Минимальные автотесты
   - Добавлен `tests/test_openai_safety.py` на safety guard и отсутствие key prefix/length в диагностике.

10. Возрастной тест уровня
   - Добавлен короткий age-adaptive тест уровня для групп 5-7, 8-10, 11-13 и 14-18.
   - Результат сохраняется в профиль и используется в AI-промптах репетитора.
   - Во фронтенде тест доступен после регистрации, из главного меню и из профиля.

11. Словарь ребенка и повторение
   - Добавлен экран словаря со статусами слов: учим, повторить, выучено.
   - Добавлен фильтр словаря и режим тренировки именно по ошибкам/словам на повторение.
   - Повторение использует накопленный `user_progress`, а не случайный список без связи с результатами.

12. История занятий
   - Добавлен API истории занятий, объединяющий ежедневные уроки и тесты по словам.
   - Добавлен экран истории с датой, результатом, баллами и быстрым переходом к уроку или словам.
   - Родительский отчет получил переход к истории занятий.

13. Умный родительский отчет
   - Отчет теперь показывает сводку словаря, слова с частыми ошибками и рекомендации.
   - Рекомендации ведут к конкретным действиям: урок, новые слова, повторение ошибок или словарь.
   - Родителю проще понять, за что платить и что ребенку делать дальше.

14. Игровые задания
   - Добавлена игра «Словесная охота»: ребенок выбирает английское слово по русскому значению.
   - Результаты игры сохраняются в историю занятий и учитываются в родительском отчете.
   - Игра начисляет баллы за правильные ответы и бонус за идеальный результат без штрафов за ошибки.

15. Учебный маршрут дня
   - На главном экране добавлена карточка «Маршрут дня» с понятным следующим шагом.
   - Маршрут учитывает тест уровня, дневной урок, словарь, слова на повторение, игры и разговорную практику.
   - Ребенок получает не просто список функций, а последовательность действий: уровень -> урок -> слова -> повторение -> игра -> разговор.

16. Расширенная база слов
   - Стартовая база увеличена с 40 до 5000 учебных словарных единиц.
   - Слова распределены по возрастам: 1250 записей для 5-7, 8-10, 11-13 и 14-18 лет.
   - База включает одиночные слова и короткие безопасные словосочетания для уроков, тестов, игр и повторения.

17. Транскрипция и озвучка слов
   - Для всех 5000 словарных единиц генерируется IPA-транскрипция.
   - В таблицу `words` добавлено поле `transcription`, оно обновляется при автосидинге.
   - В карточках новых слов, тестах, словаре и результатах тренировок добавлена кнопка озвучки слова.

18. Мотивация и достижения
   - Добавлен расчет серии ежедневных уроков: текущая серия, лучшая серия, количество учебных дней.
   - Добавлен API `/api/motivation/status` с достижениями, прогрессом и следующим рекомендуемым шагом.
   - На главном экране появился блок достижений, а также отдельный экран с бейджами и переходами к нужному режиму.

19. Логичная композиция фронта
   - Главный экран сокращен до панели дня: маршрут, разговор с репетитором, учебный раздел, прогресс и профиль.
   - Дублирующиеся пункты меню собраны в два хаба: `Учеба` и `Прогресс`.
   - Обновлен визуальный слой: крупные action-карточки, цветовые акценты, более чистые отступы и адаптация для узких экранов.

20. Профиль как отдельное подменю
   - Профиль убран из раздела `Прогресс`, чтобы аналитика обучения и настройки аккаунта не смешивались.
   - Отдельная карточка `Профиль` остается на главном экране.

## Critical / High issues, которые еще нужно закрыть

### H1. Чувствительные сообщения ребенка могут сохраняться в истории

Сейчас safety guard не повторяет адрес/телефон в ответе, но пользовательское сообщение может быть уже сохранено в `conversation_messages` до ответа модели.

Риск: ребенок случайно отправит адрес, телефон, школу или другую личную информацию, и она останется в базе.

Что сделать:

- Добавить redaction/drop до `database.add_message` для `chat/send`, `voice/text-turn`, `voice/turn`, `realtime/log`.
- Для похожих сообщений сохранять безопасную заглушку: `[personal data removed]`.
- Добавить endpoint удаления истории и понятный родительский сценарий.

### H2. Накрутка словарного прогресса и баллов

Эндпоинты ответов по словам принимают `word_id` от клиента и начисляют прогресс через `database.update_progress`.

Риск: пользователь может многократно отправлять один и тот же правильный ответ и искусственно увеличивать `correct_count`/points.

Что сделать:

- Ввести server-side attempt/session id.
- Засчитывать один ответ на одно задание один раз.
- Повторный ответ возвращать как уже обработанный без начисления баллов.

### H3. Ежедневный урок доверяет client-side `completed_steps`

`/api/daily/progress` принимает `completed_steps` от клиента.

Риск: клиент может сразу отправить максимальное значение и закрыть урок/получить награду.

Что сделать:

- Двигать прогресс только сервером после фактического прохождения шага.
- Сделать idempotent step completion: `complete_step(step_id)`.
- Не принимать произвольный счетчик прогресса от frontend.

### H4. Fallback-auth ссылки живут слишком долго

Fallback auth нужен для Telegram desktop/browser, но signed URL содержит `fa_user_id`, `fa_auth_date`, `fa_hash` и сейчас может жить до 30 дней.

Риск: если ссылка из чата переслана или попала в скриншот, доступ может сохраняться слишком долго.

Что сделать:

- Сократить TTL до 1-24 часов.
- Добавить одноразовые server-side sessions вместо длинной подписи в URL.
- Не показывать fallback URL нигде, кроме кнопок Telegram.

### H5. Leaderboard раскрывает Telegram user_id

`/api/leaderboard` возвращает `id`.

Риск: лишний стабильный идентификатор пользователя виден другим зарегистрированным пользователям.

Что сделать:

- Убрать `id` из публичного ответа.
- Оставить только имя, очки, место и безопасный avatar/initial.

### H6. Нет политики хранения/удаления детских данных

В приложении есть детские профили, история сообщений, прогресс, голосовые сценарии.

Риск: для детского продукта нужна понятная модель хранения, удаления и родительского контроля.

Что сделать:

- Добавить удаление истории диалога и профиля.
- Добавить срок хранения conversation history.
- Описать privacy policy и consent flow.

## Medium issues

1. In-memory rate limit не распределенный
   - Работает только внутри одного процесса.
   - После рестарта лимиты сбрасываются.
   - Для нескольких инстансов нужен Redis/DB-backed limiter.

2. `.venv` и `.pyc` уже отслеживаются git
   - Сейчас `git ls-files ".venv/*" "*__pycache__*" "*.pyc"` показывает тысячи файлов.
   - Это раздувает репозиторий, усложняет review и повышает риск случайного попадания мусора в build.
   - Нужно отдельным безопасным коммитом удалить их из индекса: `git rm --cached -r .venv __pycache__ data/__pycache__ handlers/__pycache__ webapp/__pycache__`.

3. README устарел
   - В документации еще есть старые сведения про SQLite и старые режимы.
   - Нужно переписать README под текущую архитектуру: PostgreSQL/Neon, Telegram auth, OpenAI, Realtime, env vars, Render.

4. Нет полноценного набора автотестов
   - Есть smoke tooling, но нет pytest suite и CI.
   - Минимум нужен набор на auth, registration gate, rate limit, safety guard, vocabulary attempts, daily progress.

5. Dockerfile запускает приложение от root
   - Лучше добавить non-root user.
   - Добавить healthcheck или отдельный `/healthz`.

6. Realtime UX все еще требует реального device QA
   - Нужно проверить iOS Telegram, Android Telegram, Telegram Desktop, плохой интернет, отказ микрофона, background/foreground.

## Low issues / улучшения

1. `openai_config_status()` теперь не раскрывает ключ, но все еще дает много operational details. Это нормально для админа, но можно сократить.
2. Frontend активно использует `innerHTML`. В ключевых чат-сообщениях используется `textContent`, а динамические поля в шаблонах в основном проходят через `esc`, но лучше добавить regression-тест на XSS.
3. Для детского UI стоит добавить явную родительскую зону и краткую подсказку, что голос записывается только после нажатия/включения режима.
